# KB-002 – Enterprise ConfigMgr to Co-management Recovery

## Overview

This knowledge base documents a production issue encountered during an enterprise migration from Microsoft Endpoint Configuration Manager (MECM) Config-Mgr to Co-Managed.

The issue affected approximately **580 Windows devices** that remained in a **Config-Mgred** state instead of transitioning to Co-Managed.

---

# Environment

- Microsoft Intune
- Microsoft Endpoint Configuration Manager (MECM/SCCM)
- Microsoft Entra ID
- Windows 10 / Windows 11
- Co-management

---

# Problem Statement

During the migration from Config-Mgr to Co-management, several devices failed to complete the transition.

Observed behaviour:

- Device remained in Config-Mgr state
- Device appeared healthy SCCM
- Microsoft Entra ID Join = YES
- Migration to Co-Managed did not complete

---

# Investigation

The following validation steps were performed:

## Step 1

Validate Microsoft Entra status.

```cmd
dsregcmd /status
```

Result:

- Microsoft Entra Joined = YES

---

## Step 2

Validated Microsoft Intune management.

Confirmed:

- Device remained Config-Mgr.

---

## Step 3

Performed recovery testing.

Recovery steps:

1. Microsoft Entra Leave
2. Microsoft Entra Join
3. Reinstall Configuration Manager Client
4. Restart device

---

# Recovery Commands

```cmd
dsregcmd /leave

dsregcmd /join
```

---

# Packaging

The recovery process was packaged as a Microsoft Endpoint Configuration Manager Application using PSAppDeployToolkit.

Deployment included:

- Enterprise logging
- Recovery automation
- Scheduled Task creation
- SYSTEM execution
- Controlled deployment

---

# Pilot Deployment

The solution was initially deployed to a small pilot group.

After successful validation, it was deployed to the remaining affected devices.

---

# Validation

Following reboot:

- SCCM client successfully reinstalled
- Device synchronized correctly
- Device transitioned from Config-Mgr to Co-managed

---

# Lessons Learned

This incident demonstrated the importance of validating device management state rather than relying solely on Microsoft Entra ID Join status.

Although the exact root cause could not be conclusively determined, the validated recovery workflow consistently restored normal management behaviour.

---

# Best Practices

✔ Validate Microsoft Entra Join status

✔ Test recovery on pilot devices

✔ Package enterprise scripts using PSAppDeployToolkit

✔ Execute deployments through MECM

✔ Validate successful Co-Managed after recovery
