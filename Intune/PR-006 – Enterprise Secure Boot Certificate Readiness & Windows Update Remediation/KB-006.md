# KB-006 – Enterprise Secure Boot Certificate Readiness & Windows Update Remediation

# Overview

Microsoft announced that existing Windows Secure Boot certificates will expire in **2026**. To ensure devices continue to trust boot components and maintain Secure Boot functionality, Microsoft introduced updated Secure Boot certificates that are delivered through Windows Update.

Enterprise administrators must prepare eligible Windows devices to receive these certificates before the existing certificates expire.

This knowledge base documents the enterprise implementation of Microsoft Intune Proactive Remediation to automate certificate readiness across the environment.

---

# Business Problem

An enterprise assessment was performed across approximately **3,800 Windows devices**.

The assessment identified devices in multiple Secure Boot certificate states:

* Certificates Active
* Certificates Inactive
* Certificates Missing
* Secure Boot Enabled
* Secure Boot Disabled

Without remediation, devices with missing or inactive certificates would not automatically receive the new Secure Boot certificates required for future Windows servicing.

---

# Microsoft Recommended Options

Microsoft published multiple remediation approaches.

## Option 1

Manual execution of Windows Update servicing commands on individual devices.

Suitable for:

* Small environments
* Manual administration
* Limited number of devices

Not suitable for enterprise-scale deployment.

---

## Option 2 (Selected)

Configure Windows Update registry settings that enable Secure Boot certificate deployment through normal Windows Update servicing.

Advantages:

* Enterprise scalable
* Fully automated
* Microsoft supported
* Delivered through normal monthly patching
* Easily deployed using Microsoft Intune Proactive Remediation

This option was selected for the enterprise implementation.

# Why Secure Boot Disabled Devices Were Not Automated

One important design consideration was understanding the difference between **Windows configuration** and **firmware configuration**.

Secure Boot is a **UEFI firmware feature**, not a Windows operating system setting.

Therefore:

* PowerShell cannot enable Secure Boot.
* Microsoft Intune cannot enable Secure Boot.
* Registry changes cannot enable Secure Boot.
* Windows Update cannot enable Secure Boot.

Devices with Secure Boot disabled required manual enablement in the system firmware (UEFI/BIOS) before they could receive Secure Boot certificate updates.

---

# Registry Configuration

The remediation configured the Windows Update policy required by Microsoft.

Registry location:

```text
HKLM\SOFTWARE\Policies\Microsoft\Windows\DataCollection
```

Configured values:

| Registry Value                  | Value |
| ------------------------------- | ----: |
| AllowTelemetry                  |     3 |
| AllowUpdateComplianceProcessing |     1 |
| AllowCommercialDataPipeline     |     1 |

These settings enable Windows Update to process and deliver Secure Boot certificate updates as part of normal servicing.

# Lessons Learned

* Enterprise assessments should always be completed before selecting a remediation strategy.
* Not all Secure Boot issues can be resolved through software.
* Microsoft Intune Proactive Remediation provides an effective platform for enterprise-wide configuration management.
* Following Microsoft guidance ensures long-term supportability and reduces operational risk.
