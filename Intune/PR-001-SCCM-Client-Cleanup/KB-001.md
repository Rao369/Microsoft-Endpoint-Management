# Overview

This Knowledge Base article describes how to safely remove the Microsoft Endpoint Configuration Manager (MECM/SCCM) client from Windows devices after migration to Microsoft Intune.

The solution uses Microsoft Intune Proactive Remediation to detect legacy SCCM client components and automatically remove them, ensuring devices are managed exclusively through Microsoft Intune.

---

# Business Scenario

Many organizations migrate from MECM/SCCM to Microsoft Intune using Co-management.

After migration, some devices continue to retain legacy SCCM client components such as:

- SCCM Client Service
- CCM Folder
- CCM Cache
- WMI Namespace
- Registry Keys
- Start Menu Shortcuts

These remnants may lead to:

- Conflicting device management
- Policy processing issues
- Application deployment failures
- Windows Update conflicts
- Increased support effort

Removing the legacy client ensures a clean transition to cloud-based endpoint management.

---

# Problem Statement

Even after successful migration to Microsoft Intune, some devices still contain MECM/SCCM client components.

Typical symptoms include:

- SCCM client still appears installed
- CCMExec service remains on the device
- Old SCCM registry entries exist
- CCM WMI namespace remains
- Windows Update source conflicts
- Device management inconsistencies

---

# Solution

Microsoft Intune Proactive Remediation is used to:

1. Detect whether legacy SCCM client components exist.
2. Automatically uninstall the SCCM client.
3. Remove remaining folders, registry keys, services and WMI namespaces.
4. Validate successful cleanup.

---

# Detection Logic

The Detection script verifies the following components:

| Component | Validation |
|------------|------------|
| C:\Windows\CCM | Folder exists |
| CCMExec.exe | Client executable |
| Start Menu | Microsoft Configuration Manager folder |

If any component exists:

Exit Code = **1**

Microsoft Intune executes the Remediation script.

If no components exist:

Exit Code = **0**

No remediation is required.

---

# Remediation Workflow

The remediation script performs the following actions:

1. Executes the native SCCM uninstall process.
2. Stops SCCM services.
3. Removes SCCM WMI namespaces.
4. Deletes SCCM registry keys.
5. Deletes SCCM folders.
6. Removes CCM Cache.
7. Removes SMSCFG.ini.
8. Removes SMS MIF files.
9. Validates cleanup.

## Step 1

Create a new Proactive Remediation package in Microsoft Intune.

---

## Step 2

Upload:

- Detection.ps1
- Remediation.ps1

---

## Step 3

Configure:

Run this script using logged-on credentials:

No

Run script in 64-bit PowerShell:

Yes

Enforce signature check:

No

## Step 4

Assign the remediation package to the required device group.

---

## Step 5

Monitor deployment status from:

Devices → Scripts and Remediations → Proactive Remediations

# Validation

After successful remediation verify:

✅ SCCM Client removed

✅ CCM folder deleted

✅ CCM Cache removed

✅ CCMExec service removed

✅ SCCM registry keys removed

✅ WMI namespace removed

✅ Device managed by Microsoft Intune only

# Logging

The remediation script creates the following log file:

```
C:\ProgramData\Microsoft\IntuneManagementExtension\Logs\PR001-SCCMCleanup.log
```

Sample log:

```
Starting SCCM Client Cleanup...

Stopping SCCM services...

Removing WMI namespaces...

Removing registry keys...

Cleanup completed successfully.
```

---

# Success Criteria

The remediation is considered successful when:

- Detection Script returns Exit Code 0
- SCCM Client no longer exists
- CCMExec service removed
- SCCM folders deleted
- Intune reports successful remediation

---

# Troubleshooting

## SCCM uninstall fails

Verify:

```
C:\Windows\CCMSetup\CCMSetup.exe
```

Review:

```
CCMSetup.log
```

---

## WMI namespace still exists

Verify:

```
root\ccm

root\cimv2\sms
```

Remove manually if required.

---

## Registry keys remain

Verify:

```
HKLM\SOFTWARE\Microsoft\CCM

HKLM\SOFTWARE\Microsoft\SMS
```

# Best Practices

- Test in a Pilot group before production deployment.
- Deploy during maintenance windows.
- Monitor Intune remediation reports.
- Validate Windows Update functionality after cleanup.
- Confirm Microsoft Entra ID and MDM enrollment remain healthy.

---

# Rollback

Rollback is generally not required.

If SCCM client needs to be restored:

- Reinstall the Configuration Manager client.
- Reassign the device to the appropriate MECM boundary.
- Confirm client registration.
