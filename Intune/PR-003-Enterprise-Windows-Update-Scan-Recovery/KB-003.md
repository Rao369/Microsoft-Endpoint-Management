# Problem Statement

During monthly Windows Update for Business (WUfB) compliance reporting, approximately **800 Windows devices** were reported with the following status:

**Quality Update Status = Device not scanned**

Although these devices were online and successfully managed through Microsoft Intune, they were not reporting recent Windows Update scan information, resulting in inaccurate compliance reporting.

---

# Business Impact

The issue affected several operational areas:

* Reduced Windows Update reporting accuracy
* Lower enterprise patch compliance visibility
* Increased number of devices appearing as "Device not scanned"
* Additional manual effort during monthly patch reporting
* Reduced confidence in Windows Update for Business dashboards

---

# Environment

* Microsoft Intune
* Windows Update for Business (WUfB)
* Windows 10 / Windows 11
* Microsoft Entra ID Joined devices
* Enterprise environment with approximately 3,800 managed endpoints

---

# Investigation

The following areas were investigated:

* Windows Update Client Operational Event Log
* Windows Update service health
* Background Intelligent Transfer Service (BITS)
* Update Orchestrator Service (UsoSvc)
* Windows Update Medic Service
* Windows Update scan history
* Microsoft Intune device synchronization

The investigation identified that many devices had stale Windows Update scan information despite remaining healthy and online.

---

# Root Cause

Affected devices were not refreshing Windows Update scan information frequently enough to satisfy Windows Update for Business reporting requirements.

In some cases:

* Required Windows Update services were stopped.
* Update orchestration had become stale.
* Device synchronization with Microsoft Intune required refreshing.

---

# Solution

A Microsoft Intune Proactive Remediation solution was developed.

## Detection

The detection script validates:

* Recent Windows Update events
* Windows Update scan freshness
* Core Windows Update service status

Devices failing validation are marked as non-compliant, triggering remediation.

---

## Remediation

The remediation script performs staged recovery:

1. Validate pending reboot status
2. Validate Windows Update services
3. Correct disabled services
4. Start required services
5. Refresh Windows Update settings
6. Trigger Windows Update scan
7. Trigger Microsoft Intune synchronization
8. Validate Windows Update event creation
9. Record remediation activity in a log file

---

# Results

| Metric                                 | Before | After |
| -------------------------------------- | -----: | ----: |
| Devices reporting "Device not scanned" |   ~800 |  ~150 |
| Enterprise Patch Compliance            |    91% |   97% |

The solution was adopted as part of the monthly operational process to improve Windows Update reporting and compliance.

---

# Lessons Learned

* Lightweight remediation is preferable to aggressive Windows Update resets.
* Validating Windows Update services before remediation reduces unnecessary actions.
* Triggering Microsoft Intune synchronization improves reporting consistency.
* Event log validation provides immediate confirmation that remediation completed successfully.
* Staged remediation minimizes disruption while improving compliance.
